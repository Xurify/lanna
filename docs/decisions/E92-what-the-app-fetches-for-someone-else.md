# E92. What the app fetches for someone else goes through one guard, every body has a cap, keys never leave in an error, and production sends a content security policy (2026-11-09, branch `chore/web-security-pass`)

**Why:** the plan to serve the app at a public address ([plans/always-on-server.md](../plans/always-on-server.md)) changes who can reach it. The review ([research/web-security-review.md](../research/web-security-review.md)) found that the tutor's page and PDF fetches would follow a URL chosen by a web page the model had read, and that this computer's own address answers without a sign-in (E21), so a prompt-injected fetch of `http://127.0.0.1:3010/api/...` would have been read on the server's behalf. It also found no cap on a request body, provider error text passed to the page in seven places, and no response headers.

**How to apply:**
- A server fetch of an address the app did not write itself goes through `safeFetch` (`src/agent/safe-fetch.ts`): http(s) on ports 80 and 443 only, no user name in the address, no single-label or `.local`/`.internal` names, every address the name resolves to must be public (loopback, private, link-local including 169.254.169.254, CGNAT, multicast, reserved and the IPv6 forms of those, including IPv4 carried in IPv4-mapped and NAT64 addresses), every redirect checked again, the connection made to the addresses that were checked, at most five redirects, a time limit, and a cap on the decoded size. Calls to a provider at a fixed address (ElevenLabs, Deepgram, YouTube's own endpoints) stay plain `fetch`. Tests replace `safeFetchSeams`, never `globalThis.fetch` (`tests/fixtures/stub-safe-fetch.ts`). A caption track is fetched only from YouTube's own `/api/timedtext`.
- Every route that takes a body starts with `bodyTooLarge(request, BODY_LIMITS.<kind>)` (`src/server/body-limit.ts`): 256 KB for JSON, 512 KB for prompts, 1 MB for cheatsheets, 4 MB for a YouTube import, 8.25 MB for a recording. The pairing and subscription routes keep their own limits. The check reads `Content-Length`; a body sent without one is bounded by Next's 10 MB request buffer (set in `next.config.ts`) and by the reverse proxy, which must set `client_max_body_size 10m` or its equivalent. `tests/body-limits.test.ts` fails when a route reads a body without the check.
- An id, name or path segment that reaches the disk is checked against a strict pattern in its store. `tests/path-ids.test.ts` calls every such route with traversal, encoded, absolute, Windows, null-byte and oversized ids and fails if a file outside the data folder changes or a route crashes. A new route with an id gets a row there.
- Provider error text that is passed on to the page goes through `redactSecrets` (`src/server/keys.ts`) before it is cut to length. `tests/secrets-leak.test.ts` seeds fake keys and sign-in tokens, calls every GET route and fails if one appears in a body or a header.
- `next.config.ts` sends `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin` (YouTube's player needs the origin; `same-origin` would break it), `Cross-Origin-Resource-Policy: same-origin` and a Permissions-Policy that gives the microphone to this page only. A production build also sends HSTS and a CSP; the dev server sends neither. A new host the browser talks to is added to `CONTENT_SECURITY_POLICY` in the same change; `tests/security-headers.test.ts` rejects `*`, `http:` and `unsafe-eval`.
- When `LH_PUBLIC_HOST` is set, the ChatGPT, Copilot and Grok sign-in controls and their redirect answer 403, because they trust the browser's origin instead of a login and their status call returns the account's email. Use API keys. Credential files left from an earlier setup (`chatgpt-credentials.json`, `github-copilot-credentials.json`, `xai-credentials.json`, beside `auth.json`) are still read by the model slots; delete them on a public server.
- Open: `script-src` still allows inline script, because Next's hydration scripts need it and a static header cannot carry a nonce; the nonce has to come from `proxy.ts`, which then also removes the CSP's last big gap. A process on the same machine that reaches `127.0.0.1` is "this computer" and passes the gate without a sign-in (E21); on a shared VPS, bind the app to a port nothing else can reach, or add a shared secret header from the reverse proxy.
