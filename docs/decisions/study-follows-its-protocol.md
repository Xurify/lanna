# The Study's code does what its protocol fixed before day 1 (2026-11-11, branch `fix/study-protocol-gaps`)

This changes [E84](E84-the-study-views-are-a-page-and.md) (the weekly check's production part is now spoken, and the switch date is no longer shown ahead) and adds to [E82](E82-an-automated-single-case-experiment-arm-input.md).

The owner, on day 1 of the input-first study: "How could we improve this? … Feel free to do all of these." The review that started it read the code against `docs/experiments/input-first-russian.md` and found the analysis, the Today row and the deviation log short of what the protocol says.

**Why:** the protocol and its decision rule were fixed before day 1, and the code that decides the result had drifted from it. The protocol's model holds the day covariates level, but the code fitted four terms. The three flags were never computed, the "five weeks of checks" rule was missing, and the make-up window for checks did not exist. `deviations.jsonl` was created but never written. The Today row counted only Russian, so the control language got no reminder. The Study page named the switch day from day 1, which the random draw is there to prevent. Bringing the analysis back to the protocol is allowed during the study. Changing the measure (the Listen grader, the picker, the lexicons) or the rule is not.

**How to apply:**
- **The model** (`fitInterruptedTimeSeries`, `runRandomizationTest`, `src/core/experiment.ts`) takes the day covariates, mean words per sentence and mean lexicon frequency rank, centered. A covariate that is missing on a counted day, or does not vary across the counted days, is left out. If the observed fit is singular with the covariates, all eleven candidate onsets are fitted without them, so they are always compared under one model. The covariates used are in `RegressionResult.covariatesUsed`.
- **The decision** is `analyzeStudy`. The result is "too early" until 8 days count on each side and 5 weeks of treatment checks are done. Beside it are the flags (time trend: the control's jump at the same day is half the treatment's or more; compliance: under 90% of listening-first minutes on allowed tasks; balance: under 70% of the minutes a day from before the switch) and the speaking comparison (production before against after the switch, and "speaking cost" at a drop of 10 points or more). They are printed and never change the verdict. `verdict.json` carries all of them.
- **A weekly check stays open through two make-up days**, then its row reads `missed`. Today and the reminder follow the open check, not the calendar week.
- **Deviations are written by the app** to `deviations.jsonl`, each once, by key: a past day with fewer than 5 typed Listen sentences in a language, a check whose window closed, and a change to the files that decide the measure. Those files are `src/core/listen.ts`, `src/server/listen.ts`, `app/api/listen/route.ts`, `components/listen/listen-player.tsx` and both lexicons. They are fingerprinted at most once a day into `measure.json`. The first look only records them, so the baseline is the code on the first day this branch runs, not the day-1 commit. `isFirstPlayUnderstood` sits in the analysis file, so its test pins it instead.
- **Today's Study row** has the anatomy of Today's line: no button of its own (E4a), both study languages with their five pips, and "check open" while a check is open. The sidebar badge and the 20:30 reminder read the same way: they count both languages and name only the one still short.
- **The switch day stays unnamed until it comes.** Before it, the page says the plan switches on a random day between the first and last candidate, and the chart marks only that window. After it, the page names the date, as before. The day is still written in `experiment.json`, `summary.md`, E82 and the experiment test, so this only keeps it out of the screen the learner reads every day.
- **The production part of the weekly check is spoken** when a speech-to-text key is set and the browser can record. The learner presses the microphone and the clip is written down in the check's language (`/api/stt` takes `lang`), then matched word by word as before. Each item records its engine (`stt:<engine>` or `typed`). With no key, no microphone, or a failed transcription, that item is typed and says so. The first check is day 7 (17 November), so no check has been taken under the old typed form.

**Not changed:** the measure, the decision rule, the onset, the pools, and the protocol file (its hash is in `experiment.json`).
