# One file per decision, no changelog, and LANGHARNESS.md holds only what the app cannot show (2026-11-11, branch `docs/split-decisions-drop-changelog`)

The owner, on GitHub's "This branch has conflicts that must be resolved" for `LANGHARNESS.md`, `docs/CHANGELOG-2026-11.md` and `docs/DECISIONS.md`: "should we remove them in general. Idk if they are really that helpful to have and are kinda annoying", then "this stuff just causes so many fucking conflicts".

**Why:** every pull request appended to the end of the same three files, so any two branches open at once conflicted at merge. PR #190 and `fix/listen-miss-marks` both took E103 on the same day; E50 and E86 had already been given twice. `docs/DECISIONS.md` had grown to 276 KB (about 70,000 tokens), more than an agent reads before changing something, so "read this first" was not being followed. `docs/CHANGELOG-2026-11.md` reached 160 KB in eleven days and repeated each PR's description: what changed, what was checked, what is not verified. `LANGHARNESS.md` described every feature in rows of up to 3,600 characters, so two PRs on one feature collided on one line.

**How to apply:**
- **Decisions** are one file each in this folder, named after what they decide, with no number ([README.md](README.md)). A new file never conflicts. The 120 decisions of `docs/DECISIONS.md` are split into files that keep their id at the front of the name, so "E38" in a comment still leads to `E38-*.md`. Their text is unchanged, except that E69, E74 and W4 now point to the pull request's description and this folder instead of the changelog and the old file.
- **No changelog.** What was built, what was checked and what is not verified goes in the pull request's description, which already carried it with screenshots. Git history keeps `docs/CHANGELOG-2026-10.md` and `docs/CHANGELOG-2026-11.md`.
- **`LANGHARNESS.md`** keeps what the app cannot show: the pages and their routes, the data folder, pairing a phone, the keys and commands, refreshing the curriculum, the limits and how to run the tests. What a page does is on the page and on Sources (E63).
- **Where they were named** (`CLAUDE.md`, `AGENTS.md`, the skills, the PR template, the plans, research notes and code comments), the links now point to the decision's file or to this folder.
