# E93. The app can be served at a public address behind a password, and the proxy proves itself with a secret (2026-11-09, branch `feat/web-sign-in`)

**Why:** the owner wants to use LangHarness from a phone with the PC off, at an address of its own like flags.games, in any browser with no Tailscale app ([plans/always-on-server.md](../plans/always-on-server.md), route W). Until now nothing reached the app but this computer and paired tailnet devices (E21), so the app had no login. This reverses E7 and E21's "no public address" for the one deployment that asks for it. Tailscale stays and works beside it.

**How to apply:**
- **Off unless `LH_PUBLIC_HOST` is set** (a host name such as `learn.example.com`: no scheme, port or path). Unset, every rule of E21 is unchanged.
- **Every request at the public address must carry `LH_PROXY_SECRET`** (32 characters or more) in `X-LH-Proxy-Secret`, name the public host in both `Host` and `X-Forwarded-Host`, and say `X-Forwarded-Proto: https`. Next 16 does not hand the TCP peer to `proxy.ts`, and every `x-forwarded-*` header is either filled in by Next (`??=` in `base-server.js`) or sent by the client, so none of them can prove a request came through the reverse proxy; a secret the proxy adds can. A client's own copy is overwritten by the proxy's `proxy_set_header`. Without the secret, with a wrong one, or with a secret too short to configure, the request is refused with a message that names the problem.
- **Nothing at the public address is "this computer".** E21 lets a request that names only loopback and carries no proxy header pass as this computer. nginx sends the upstream's own name (`127.0.0.1:3010`) as `Host` unless told otherwise, so a default config would have opened everything. In public mode the local shortcut is off: the sign-in is required for everyone, and a wrong `Host` is refused. Checked against nginx 1.24 with its default `Host`: refused; with the guide's config: served. Inside Docker every connection reaches the app from the bridge address (`172.17.0.1` on the default network), whoever sent it, so the sender's address tells the app nothing and is never used for a decision; `tests/web-access.test.ts` runs a loopback `Host` from `172.17.0.1`, with and without `X-Real-IP` and `Forwarded`, a right secret and a signed-in browser, and every one is refused at the public address. With `LH_PUBLIC_HOST` unset, desktop and dev behave as E21 says.
- **Sign-in:** `/login` and one POST, `/api/access/login`. One owner password, scrypt (N = 2^17, r = 8, p = 1, 16-byte salt, 32-byte key, OWASP's minimum), in `web-login.json` beside `access.json`, mode 0600, never in git. The record names its own parameters. 12 to 200 characters. `npm run web:password` sets or changes it (hidden prompt, or `LH_WEB_PASSWORD_FILE`, `-` for standard input). The first password also turns web access on. A right password creates the E21 device session (random token, only its SHA-256 digest kept, 180 days, HttpOnly, SameSite=Lax, Secure). Settings → Devices lists it as "Signed in" and signs it out; signing out the device you are on clears its cookie and returns to `/login`.
- **Everything else needs a session:** pages redirect to `/login?next=…` (the next path is checked: inside the app, never `/login` or `/pair`), the API answers 401 `login_required`. Pairing is not offered at the public address.
- **Changing a state needs the page's own Origin:** a POST, PUT, PATCH or DELETE must carry `Origin: https://<LH_PUBLIC_HOST>`; a missing one is refused. This is on top of SameSite=Lax.
- **Tries are limited and the limit is kept in the file:** five tries a minute per address, then 15 minutes locked; 40 tries an hour across all addresses, then 15 minutes locked for everyone (so a botnet is stopped, and the owner can be locked out for a while: `npm run web:password` clears it). A try is counted under one lock before the slow hash runs and is given back only when the password was right, so eight parallel guesses count as eight (tested). The address is the **last** entry of `X-Forwarded-For`, the one nginx's `$proxy_add_x_forwarded_for` appended; the entries before it are the client's. Behind a second proxy (a CDN) every client shares that proxy's address, and only the global limit applies.
- **A changed password signs every device out. Turning web access off (Settings → Devices, or `npm run remote:off`) signs everyone out and the sign-in page answers 403.** An unreadable `web-login.json` means no password, so nobody can sign in.
- **`npm run remote:code`** prints a pairing code in the terminal (`-- --enable` turns remote access on first), for a computer with no screen where the first code cannot be made in Settings.
- Reverse-proxy settings are in [remote-access.md](../remote-access.md).
- **Tailscale and the public address work together (owner, 2026-11-10: "I want both").** A request addressed by a tailnet name takes the existing pairing path even while `LH_PUBLIC_HOST` is set, so a phone on the tailnet and a browser at the public address can both be used. They share one switch (`access.json`): setting the web password turns remote access on for both, and turning it off signs both out. With `LH_PUBLIC_HOST` set, a loopback request is refused like any other that lacks the proxy secret, so `node cli/remote-code.mjs` replaces the SSH tunnel for the first pairing code.
- **The sign-in page is one calm column, not a card (owner, 2026-11-10: "improve the login page design and add the app's name and logo", then "let's take more of a Spline approach, much cleaner and less blocky").** Looked at on Mobbin: Spline's login, Tally's password gate and ChatGPT's password step have no box around the form; n8n, Amazon, Zendesk and beehiiv do, and read as blocky. So: the rounded app icon (the teal tile, drawn inline so the page needs no file the gate would turn away), "Welcome to LangHarness" with the wordmark colors, one line, the field (`.q-field`, with an eye toggle inside, no native widget), the main button (`.q-btn.primary.wide`) and a quiet 180-day note, centered on the ground. The error line has two lines reserved, so a message never moves anything. Not taken from Spline: its gradient orb (no gradients, E32). No stock shadcn field or button, no shadow.

**Unverified:** a real VPS, a real certificate and domain, Caddy (only nginx was run, locally, on plain HTTP with `X-Forwarded-Proto` set by the config), Cloudflare or another CDN in front, a phone or an iPad, and the password manager on iOS. Streaming pages (server events) through nginx were not run with `proxy_buffering off` under load. The cookie is not `__Host-` prefixed.
